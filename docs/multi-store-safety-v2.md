# 多店铺安全运营 V2.0（本地版）

## 操作入口

进入「账号管理 → 账号安全中心 → 展开运营总览」。无需额外付费服务；读取的是本地已同步数据，不主动刷新第三方平台。

| 模块 | 本版本能力 |
| --- | --- |
| 安全调度 | 所有账号的商品采集、雷达单目标访问、账号周期任务及手动账号计划任务使用同一进程本地执行权；忙时拒绝，不积压、不自动补发；保留原有按账号节流规则。 |
| 多账号任务管理 | 账号状态、异常原因、批量停用与重新查询；每个店铺最近 20 条账号计划任务记录，原有账号卡片负责单店配置和启停。 |
| 去重 | 保留订单自动化、一次性消息及账号任务的持久化幂等约束；重领账号任务时复核账号、类型、目标、日期；已经停用的账号不领取下一笔任务，部分执行的批次转人工核对。 |
| 异常日志 | 规则审计最近 30 条，支持失败、待人工核对和跳过；可主动读取管理员运行错误最近 100 条中的本人账号摘要。原始诊断仍在既有日志页，跳过事件不一定都是重复任务。 |
| 经营总览 | 全部本人店铺或指定店铺，今天、最近 7 天、最近 30 天；销售额、计入销售的订单数、已完成订单金额、取消订单金额。 |

## 安全边界

- 批量停用会逐个调用既有账号停用接口，再核对本地持久化状态；不是原子事务，也不是全局网络断开。已发送的请求可能完成。未确认的状态要人工核对，恢复需要逐个操作。
- 共享执行权是单进程内的非阻塞闸门，不影响正常订单处理和客服消息；不等于覆盖所有网络请求的全局限流或分布式任务队列。采集与计划任务争用时，不启动新请求。
- 雷达遇到需要停止的错误会关闭当前用户定时计划；数据库写入失败时，本进程保留阻断，重启前必须人工核对。重新配置计划必须确认平台授权及账号状态。
- 运营总览只读取本地摘要，不读取或显示凭证、卡密和买家消息。管理员运行日志仍受原权限控制，查询结果按本人账号范围过滤；无账号标识的系统异常在原运行日志页。
- 销售额基于已发货与已完成订单，取消订单金额不代表平台实际退款，数据不等于实时到账、利润或平台余额。未同步订单不会被统计。
- 不修改滑块、登录、网络身份和平台验证策略。任何外部操作应遵守平台规则并具有必要授权；不得将安全门禁理解为规避风控的能力。

## 验证

使用临时 SQLite 数据库、模拟客户端和前端 API 替身验证：跨账号并发拒绝、任务重领身份一致性、停止状态、不同用户销售数据隔离、前端部分读取失败与管理员日志显式查询。不使用真实平台账号。发布前仍需按仓库要求进行完整门禁、数据库方言和部署验收。
